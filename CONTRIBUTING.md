# Contributing to FloriaApps

Thank you for your interest in contributing to FloriaApps.

We welcome bug reports, feature requests, documentation improvements, and code contributions.

## Before contributing

Before opening an issue or pull request, please:

1. Check whether an existing issue already covers the topic.
2. Read the documentation for the project.
3. Make sure your change is relevant to the project.
4. Keep changes focused and easy to review.

## Reporting bugs

Use the bug report template whenever possible.

Include:
- A clear description of the problem
- Steps to reproduce it
- Expected behavior
- Actual behavior
- Relevant logs or error messages
- Operating system and environment information
- Project version

Avoid including passwords, tokens, API keys, or other sensitive information.

## Requesting features

Use the feature request template when available.

Explain:
- What problem the feature would solve
- How you would expect it to work
- Why it would be useful
- Any relevant examples or alternatives

## Pull requests

Before opening a pull request:

- Make sure your changes are focused.
- Update documentation when necessary.
- Add or update tests when appropriate.
- Run the project's available checks locally.
- Make sure CI passes.
- Keep commits clear and descriptive.

Pull requests should explain:

- What changed
- Why it changed
- How it was tested

## Code style

Follow the conventions already established by the project.

Do not introduce unrelated formatting changes or refactors unless they are necessary for the contribution.

## Commit messages

Use clear and concise commit messages.

Examples:

```text
feat: add service integration
fix: handle authentication error
docs: update installation guide
refactor: simplify adapter interface
test: add adapter coverage
chore: update dependencies
```

## Review process

Pull requests may be reviewed by maintainers before being merged.

Maintainers may request changes, clarification, tests, or documentation updates.

Please keep discussions respectful and focused on the code and the project.
